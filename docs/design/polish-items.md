# Polish items (overnight build, slug `polish`)

Six small open items, each done end to end. Decisions per item; details live in the linked docs.

1. **API key expiry e-mails** (`packages/developer/src/worker.ts`). The daily job emits `ApiKeyExpiring` (threshold `7d` or `expiry_day`) in the same transaction that sets the marker column (`expiry_notice_7d_at` / `expiry_notice_day_at`), claimed with a conditional update so two workers cannot both send. A key first seen inside its last 24 hours gets only the expiry-day notice. `@cnote/notifications` observes the event (`developer.api_key_expiring`, `developer.api_key_expires_today`, category security, en + hi seed copy in the DB template). The secret is never in the event.
2. **Localised failure pages (buyer web)**. Hindi `/hi/...` already worked for `[locale]/error|not-found` and `(app)/*`. The gaps were the root `error.tsx`, `not-found.tsx` (any URL no route matches, e.g. `/hi/typo`) and `global-error.tsx`. They cannot rely on a next-intl provider (a failed locale layout, or no layout at all), and the 404 is prerendered once for every URL, so they read the language from the browser URL prefix, then the `cnote_locale` cookie, after hydration (`useSyncExternalStore`, English during SSR/hydration), and set `<html lang>`. Copy is a small mirror (`src/i18n/fatal-copy.ts`) of `errors.*` for all 8 locales, enforced equal to the catalogues by `test/fatal-copy.test.ts`, so these bundles do not ship the whole catalogue. New key `errors.reference` in all 8 catalogues. e2e: `e2e/a11y/not-found.spec.ts` (written, not run).
3. **Seller cookie policy page** and 4. **seller consent account sync**: see `docs/design/cookie-consent.md` ("Seller app: policy page and account sync"). Policy v2 + snapshot v2; separate ledger purposes `seller_*_cookies` (new enum values, migration `seller_cookie_consent_purposes`). Mobbin: not consulted; the page mirrors the existing buyer `/cookies` page and reuses its table component.
5. **DPDP**: (a) inactivity erasure with 48-hour notice and (b) nominee right: `docs/compliance/retention-schedule.md`, `docs/compliance/nominee-right.md`, `docs/compliance/dpdp-checklist.md`. New durable `persons.last_active_at` (backfilled), `inactivity_erasure_notices`, `data_nominees`, `nominee_requests` (migrations `dpdp_inactivity_notice_and_nominee`, `backfill_person_last_active`). Inactivity erasure ships OFF. Mobbin: not consulted for the nominee screens (plain forms built from `@cnote/ui` Field/Input/Select, same as the account-erasure form).
6. **CSP**: `docs/security/security-architecture.md` "Static pages and CSP": SRI enabled, hash mode and the `pnpm csp:hashes` generator built; `unsafe-inline` remains on static pages by default and the residual is documented.
